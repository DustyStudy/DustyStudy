# Threat-informed hardening log

Changes made to the public repos in response to AWS attack techniques and public threat reporting. Each entry names the technique, links public reporting of attackers using it, and describes what the repo covered before and the control that was added.

An entry means the repo now has a control for that technique. It does not mean the technique is fully prevented. Each linked PR lists what was tested and what was not.

"Seen in the wild" links go to incident response or threat research that documents real attackers using the technique. [AWS CIRT's Threat Technique Catalog](https://aws-samples.github.io/threat-technique-catalog-for-aws/) lists techniques observed in real AWS customer security events.

Severity rates the technique itself: what an attacker gains when it works against an environment it applies to. It is my own rating, not a CVSS score, and it does not describe the state of these repos. Critical means administrative control of an account or organization. High means stolen credentials or data, or code running on a workload. Medium means abuse of a service, such as cost or outbound mail, without wider access.

Newest first.
